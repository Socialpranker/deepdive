## Приложение: правила, вынесенные из SKILL.md

SKILL.md держит только короткие версии; полные формулировки лежат здесь, ничего не потеряно. Читать при входе в Фазу 4, 5 и 6.

**Выход прогона.** `<slug>/`: `plan.md` (+ changelog §16, notes §15; отдельного `_changelog.md` нет), `state.md` (Фаза 4, перезаписывается каждый раунд, medium/deep), `sources.csv`, `claims.csv`, `numbers.csv` и `outline.md` (Фаза 6, medium/deep), `figures.csv` (6.9, только по `num_id` из `numbers.csv`), `sources/NN_slug.md` (один файл = один источник), `evidence/CN.md` (5.5, relevant-only цитаты), `findings/FN_*.md` (опц., Z6 в `blocks/close.md`), `refresh_targets.md` (7), `memo.md` (6, всегда), `application.md` (8, всегда), `.verify/` (`authority.json` 5.5 · `wiki_pairs.json` 5.7 · `wiki_ingest.json` finish-up, всегда · `citations|faithfulness|qualifiers|constructs.json` 6.5 по оси на файл), `diffs/<date>_delta.md` (update), `README.md` (6.9, генерится), `readout.md` (6.9, после humanizer-ru), `<date>_<slug>.html` и `<date>_<slug>_full.{pdf,docx}` (человеку), `<date>_<genre>.html` (технический, сноски на полях), `<date>_<genre>.md` (технический финал: qa|explainer|decision|landscape|validation|custom). Кросс-прогонная вики — `~/.claude/research/wiki/`, вне прогона.

**Правила (полные формулировки).**
- Не пропускать: `discover existing` и reframing; Plan-review gate в medium/deep (для deep гейт без ожидания ответа = не гейт); Фазы 5.5, 5.7 и multi-angle red team в medium/deep; gap-волну; Фазу 8 «потому что и так ясно»; на вилки не отвечать за пользователя. Не запускать medium/deep без if-then вилки Decision Spec. Не завершать синтез финалом «it depends».
- Фаза 5.7: не объявлять конфликт, не показав обе стороны с `as_of` и корнями; `unknown` — карантин, не «сойдёт»; не молчать про срез по `MAX_ADJUDICATED` (непроверенные пары ≠ отсутствие противоречий); не чинить противоречие выбором «более свежего». Вики руками не править, внутри проекта не заводить, `wiki_ingest` по глубине не гейтить.
- Уверенность: `root:` не оставлять пустым, `discovery_path:` не копировать между источниками (3-е и 4-е условия триангуляции); не давать `triangulated` при непогашенном `dissent` от Primary/`credibility ≥ 4` (это `contested`) и не гасить dissent понижением credibility несогласного; без primary не выше `medium`; не строить выводы на источниках с `total < 8`; тонкий источник (<2 дословных цитат или `access:` PARTIAL/closed) — не плечо триангуляции: перефетчить лестницей или понизить статус тезиса; утверждение без ссылки на `sources/NN.md` не оставлять. Заголовки `claims.csv`/`numbers.csv` и форма `.verify/faithfulness.json`/`qualifiers.json` — канон `source_scoring.md`/`runtime_verification.md`, любой другой вариант гейт роняет.
- Числа: число без производителя (`origin_kind: unknown` / `chain_len ≥ 2` / нет `data_as_of`) не идёт в `memo.md`/TL;DR/F9 и не `high`; процент/долю/рост не считать прозой — только `numbers.csv` с `formula`+`inputs`; числа, которого нет в `numbers.csv`, в отчёте нет; палитру фигур валидирует скрипт; числа не искать в вебе, если есть покрывающий endpoint в `stat_sources/`/`api_sources/`.
- Фаза 4: не разводить fetch-агентов только по подтемам, но и по осям поиска (EN-академия / RU + регуляторы / практики / реестры); дубли URL не выбрасывать молча — считать `overlap_rate` в `plan.md` §15 (совпадение — замер конформизма, не подтверждение); не передавать во второй раунд находки соседей, только дыры; `state.md` не дописывать; fetch-агентов на opus «для качества» не поднимать; fetch+save — `deepdive-fetcher` с явным диапазоном номеров, red team — `deepdive-redteam`, `explore-haiku`/Explore — только read-only; суб-агентов запускать параллельно в одном сообщении.
- Fetch: не обходить WebFetch произвольным `bash`/`curl`; санкционированный fallback — `scripts/fetch_source.py` (robots.txt, санитайзинг от prompt injection, `fetch_tier`); вывод ручного `curl` в `sources/` не класть. `auth-wall` и `antibot` для него терминальны — дальше `channels.md` §«Bot-block ≠ paywall» или `api_sources/`.
- Фаза 5.5: `sources/NN.md` не переписывать (архив), фильтровать по релевантности фрагмента к claim, а не по `total`. Фаза 6.5: не доверять наличию ссылки — entailment по дословной цитате; вердикты в `.verify/*.json`, не пересчитывать в rubric/F10; пары брать из `evidence/`, не пересканировать `sources/`; чинить отчёт, не ledger. Именованный фреймворк/«закон» — только с `[sNN]` или пометкой «наша рамка». Из одного источника в отчёте не больше 25 слов дословно; лимиты не складываются в один длинный блок.
- Синтез: не писать отчёт одним проходом по пулу; `triangulated`/`contested` claim не оставлять вне `outline.md`; `memo.md` не сливать в большой документ; DOCX не для чтения — читают PDF и HTML.
- Человеческая версия: не выводить вырезанием кодов из технической; не отдавать `memo.md`/технический отчёт вместо страницы; не пропускать `humanizer-ru` по `readout.md` (технический им не чистить — точность важнее гладкости); дословные цитаты не тащить — там тип материала (цифра, факт, исследование, позиция, продукт, кейс, норма, «не нашли»).
- Не сжимать `sources/` в один файл, не выводить результат только в чат, не гонять шаги finish-up поодиночке вместо `finish.py`.

**Loop Фазы 4** (формулировка из SKILL.md): раунд 1 = пул кандидатов (с snowball) → отбор по квотам → чтение; второй раунд по переменной решения обязателен; цикл goal-check → bounded deviation → circuit breaker (2 раунда без нового ⇒ стоп, остаток в Open Questions).

**Update.** Pre-flight: `plan.md`, `refresh_targets.md` (нет — сгенерируй по Z11), последний отчёт. Четыре категории дельты с date-фильтром от last_research_date: new entrants · entity diff · numbers refresh · adversarial trigger. Verified-no-change — тоже результат. ## Собственный замер как источник (урок прогона 3d-meshes-code-rendered, 2026-10-22)

Красная команда сняла с первого замера половину выводов; чтобы не повторять:
- Сырой вывод скрипта пишется в `evidence/*.log` до карточки источника; «Key quotes» берутся из лога дословно, не пересказом.
- Минимум два отдельных процесса и разный порядок кадров/входов; время — медиана ≥8 прогонов после прогрева, не одиночное значение. Первый прогон считается разведкой.
- В лог идут версии (браузер, библиотека) и строка рендерера/окружения; без них «тот же бинарь» не утверждается.
- Если проверяемая система уже содержит политику по теме (флаги, кэш, закрепление бэкенда), сначала `grep` по ней: рекомендация не должна ей противоречить.
- Источник `file://` не проверяется на живость (`check_citations.py` метит `LOCAL_FILE`); `finish.py` сам подтягивает `requests` через `uv`.
