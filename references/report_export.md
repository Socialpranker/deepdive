# Экспорт отчёта — Фаза 6.9

Собирает `<date>_<genre>.md` в HTML, PDF и DOCX. Запускается после Фазы 6.5 (verify),
до Фазы 8 (decision walkthrough): исполняют решение по собранному документу.

```bash
uv run scripts/build_report.py <run>
uv run scripts/build_report.py <run> --formats html,pdf     # без DOCX
```

Регистр — **отчёт на 15–20 страниц под одно решение.** Не справочник: оглавления,
версионирования секций и дельта-разметки здесь нет намеренно. Живой свод на 50+
страниц — другая вёрстка, а не настройка этой.

`memo.md` **в документ не сливается** и остаётся отдельной страницей. Никто не читает
двадцать страниц перед решением; если memo растворить внутри, потеряется ровно та
часть, которую точно прочтут.

## Что сборка делает сверх конвертации

| Шаг | Зачем |
|---|---|
| Фигуры из ledger'а | Число без строки в `numbers.csv` нарисовать нельзя — сборка падает |
| Сноски на поля | Источник виден, не покидая абзаца (аппарат Тафти) |
| Резолв `[sNN]` | Битая ссылка роняет сборку: в 20 страницах её не находят глазами |
| Приложение источников | Генерится из `sources.csv`, включая `access` и `fetch_tier` |
| Схемы Mermaid | ```` ```mermaid ```` вырезается до pandoc и рисуется `mmdc`; схема, которую рендер не взял, роняет сборку |

Три отдельно поддерживаемых файла — это три расходящихся отчёта, а не один в трёх
видах. Поэтому источник один: markdown плюс CSV.

## figures.csv

Лежит в папке прогона рядом с `numbers.csv`. Одна строка — одна фигура.

| Поле | Значение |
|---|---|
| `fig_id` | `F1`, `F2`, … — по нему фигура вставляется в текст токеном `{{fig:F1}}` |
| `form` | `bar` · `slope` · `share` · `dot` · `line` |
| `numbers` | `num_id` через `;` — **только из `numbers.csv`** |
| `labels` | подписи рядов через `;`, по позиции; пусто — берётся `num_id` |
| `notes` | примечание к ряду без значения (например «фид мёртв (404)») |
| `title` | обязателен: фигура без заголовка нечитаема |
| `subtitle` | уточнение — что за срез, какая выборка |
| `caption` | подпись под рисунком: что здесь видно, а не что нарисовано |
| `legend` | подпись легенды для `dot`; по умолчанию — единица измерения |

В тексте: `{{fig:F1}}` на отдельной строке. Нумерация «Рис. N» — по порядку строк
в `figures.csv`, не по порядку в тексте.

## Выбор формы

Форму диктует работа данных, а не вкус. Пирога в наборе нет намеренно: доли не
сравниваются углами.

| Работа данных | Форма | Почему |
|---|---|---|
| Величина по категориям | `bar` | Длина сравнивается точнее угла и площади |
| Изменение между двумя точками | `slope` | Наклон читается мгновенно; два столбца — нет |
| Часть от целого | `share` | Рамка показывает знаменатель: доля без него врёт |
| Сравнение по объектам | `dot` | Компактно, и пустое значение видно как пустое |
| Ряд во времени (N8) | `line` | ≥3 точек, подписаны только края |

**Отсутствие данных рисуется пунктиром, а не нулём и не пропуском.** Пустая строка
в `value` даёт штриховую засечку с текстом из `notes`. Ноль — это утверждение
«измерили и получили ноль»; пропуск — «мы про это молчим». Ни то, ни другое не равно
«данных нет».

## Провенанс в графике

Подвал каждой фигуры собирается из ledger'а, а не пишется руками: источники `[sNN]`,
диапазон `as_of`, и формула для `derived`. Читатель пересчитывает производное число
не отходя от рисунка.

`check_number_arithmetic.py` уже проверяет, что `derived` сходится с `formula`, а
`share`-группы дают 100 ± 0,5. График, построенный из ledger'а, наследует эту
проверку бесплатно.

## Сноски

Автор пишет обычные markdown-сноски:

```markdown
Доля выросла вдвое [s04].[^base]

[^base]: База 2025 года пересчитана по методике 2026 — сопоставимость ограничена.
```

Для HTML и PDF сноска уезжает на поле напротив своей строки. Для DOCX остаётся
сноской: **боковых полей в Word нет**, и сплющить её в абзац посреди текста было бы
хуже. Отсюда правило: DOCX — формат для правок и согласования, читают PDF и HTML.

Расхождение «сносок в документе N, перенесено M» роняет сборку. Молча потерянная
сноска неотличима от её отсутствия: текст выглядит целым, а источник утверждения
исчез.

## Вёрстка

Направление — **e-ink/paper** (`assets/report.css`), выбрано по регистру «читать
длинный текст»: тонированная бумага `#f5f2ea`, чернила `#2b2926` (контраст ~12:1,
не максимальный — от максимального устают), колонка 62 знака, засечный Charter.
Ноль теней, ноль градиентов. **Иерархия держится на кегле и вертикальном ритме:
убери цвет — структура не изменится.**

Палитра фигур `#0072a8 · #c9560c · #8a4fb0` прогнана через
`dataviz/scripts/validate_palette.js` на бумажной и на тёмной подложке — шесть
проверок PASS. Зелёный исключён сознательно: пара зелёный↔ржавый давала
CVD-разделение 3,9 при пороге 8.

Менять палитру — только заново прогнав валидатор. На глаз не подбирается: первая
попытка провалилась по двум проверкам из шести.

## Схемы Mermaid

Блоки E13 `flow-diagram` и M9 `network-graph` пишутся как обычный fence в тексте
отчёта. Дальше — конвейер:

1. `tokenize` вырезает каждый fence до pandoc и ставит `{{dia:DN}}`. Без этого
   pandoc уносит схему в `<pre>` как код.
2. `mmdc` рисует SVG в теме e-ink из `assets/report.css` (базовые цвета заданы в
   `mermaid_figures.THEME`, а не подбираются в каждой схеме).
3. HTML и PDF получают SVG инлайном, DOCX — картинкой; подпись берётся из
   `%% caption: <текст>` внутри fence.

**Нумерация отдельная — «Схема N», а не «Рис. N».** У фигуры есть строка в
`numbers.csv`, у схемы её нет и быть не может: схема отвечает за структуру, не за
число. Общий счётчик означал бы ссылку «Рис. 4» на картинку, за которой не стоит
ни одного проверяемого значения.

**Ограничения на число узлов нет.** Оно было, пока схемы рисовались в ASCII
руками. Делить схему надо по смыслу — когда в одну картинку попали два разных
вопроса, — а не по счёту узлов.

**id корневого `<svg>` уникален на документ** (`-I dia-DN`): mermaid скоупит свои
стили по id, и дефолтный `my-svg` у двух схем означает, что стили второй красят
первую.

## Зависимости

| Что | Для чего | Если нет |
|---|---|---|
| `pandoc` | все форматы | сборка падает |
| Chromium / Chrome | PDF, рендер схем | PDF пропускается, HTML и DOCX собираются |
| `mmdc` + `puppeteer` | схемы Mermaid | есть fence → сборка падает; с `--no-strict` схема остаётся кодом в тексте |

LaTeX не нужен: PDF печатается headless-браузером из HTML. Chromium уже стоит под
fetch-лестницу Фазы 4.2.

Рендерер схем ставится один раз и **без второго Chromium** — он берёт тот же
бинарь, что печатает PDF:

```bash
PUPPETEER_SKIP_DOWNLOAD=1 npm i -g @mermaid-js/mermaid-cli puppeteer
```

`puppeteer` здесь обязателен отдельной строкой: у `mermaid-cli` он peer-зависимость
и сам не подтягивается — без него `mmdc` падает с `ERR_MODULE_NOT_FOUND`.

## Чего здесь нет

- Оглавления и версионирования секций — регистр не тот, см. выше.
- Тёмной темы для печати: документ печатают на бумаге.
- Автоматического выбора формы по данным. Форму выбирает автор — это содержательное
  решение, а не оформление.
