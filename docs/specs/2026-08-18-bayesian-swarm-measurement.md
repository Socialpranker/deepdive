# Замер байесовского роя — контрольная группа

## Назначение

Контрольный замер верифицирует, что пакет (Task 1–9) выполнен корректно: аллокатор распределяет свободный бюджет адаптивно, покрытие триангуляции не нарушено, и система обучается на наблюдениях.

Без замера утверждение «стало лучше» — вера, а не измерение: аллокатор может исправно сэмплить Thompson, но исход (долю triangulated claims) не менять, потому что выигрыш сидит в уменьшении пустых агентов, а не в качестве.

## Дизайн замера

**5 тем, по одной на жанр из `genres.md`.** Каждая прогоняется дважды: с аллокатором и без (режим аллокатора = off). Вопрос, depth и все прочие параметры идентичны между парой.

**Выбор тем:** одна тема на жанр, обложить диапазон от мелкого факта до тесного анализа.

## Критерий успеха

Замер успешен, если:

1. **Триангуляция не упала:** доля `triangulated` в режиме on ≥ доля в режиме off для каждой темы
2. **Пустые агенты снизились:** число пустых суб-агентов в режиме on < число в режиме off (усредняя по темам)

Рост доли triangulated — бонус, не требование: аллокатор экономит бюджет, а не повышает достоверность исходов. Главное — не сломать.

## Критерий отката

**Замер не прошел (откатываем Task 1–9), если:**

Доля `triangulated` упала хотя бы на одной теме (off > on в одной паре). Это значит свободная часть бюджета съела покрытие триангуляции, и граница между обязательной и свободной частью проведена неверно.

## Рабочие процедуры

### 1. Как выключить аллокатор для контрольной группы

**В текущем коде (по состоянию на 2026-08-18) переменной окружения `DEEPDIVE_SWARM` нет.** Аллокатор ещё не встроен в основной loop (см. docs/specs/2026-08-18-bayesian-swarm-design.md §5), поэтому вызовов `Budget.allocate` в production коде нет.

**Способ выключения, работающий с текущим кодом:**

Поскольку аллокатор будет встроен в `run_search_loop` (runner/adaptive.py:217), при встраивании добавить проверку:

```python
import os

if os.environ.get("DEEPDIVE_SWARM", "on").lower() != "off":
    allocated_channels, fallback_used = budget.allocate(
        qclass=qclass,
        free_slots=free_slots,
        candidates=candidates,
        priors=priors,
        groups=groups,
        rng=random.Random()
    )
else:
    # режим off: равномерное распределение
    allocated_channels = candidates[:free_slots]
    fallback_used = False
```

**Для контрольной группы (режим off):**

```bash
export DEEPDIVE_SWARM=off
# запустить прогон как обычно
```

**Для тестовой группы (режим on):**

```bash
# переменная окружения не задана или DEEPDIVE_SWARM=on
# запустить прогон как обычно
```

Режим off даст равномерное распределение свободного бюджета (список кандидатов в исходном порядке), что и требуется для контрольной группы. Fallback-флаг будет ложным, потому что это не сбой приоров, а сознательное отключение.

### 2. Откуда брать числа для таблицы

**2.1 Доля triangulated claims**

Источник: `claims.csv` в директории прогона.

Формат (см. примеры в tests/fixtures/run_mini/claims.csv):

```csv
claim_id,sources,source_types,roots,paths,status,confidence,primary_source,source_caveat,dissent,as_of
c1,s1,academic,study-smith-2024,academic,triangulated,high,s1,,,2026-08-18
c2,s2,web,own,web-general,single-root,low,,,s2,2026-08-18
```

Колонка **`status`** содержит:
- `triangulated` — улика, зафиксированная ≥3 источниками, ≥2 типа, ≥2 корня (требование source_scoring.md)
- `single-root` — одна улика, один корень
- Прочие значения (см. source_scoring.md)

**Расчёт:**
```
triangulated = count(rows where status == "triangulated")
всего = count(rows)
доля = triangulated / всего (если всего == 0: 0%)
```

**2.2 Число пустых суб-агентов**

Источник: `sources/` директория в прогоне.

Суб-агент возвращает результат в `sources/NN.md` (где NN — порядковый номер по dispatch). Каждый файл — это один запрос одного агента.

**Формат источника** (frontmatter из sources/NN.md):

```yaml
---
id: s1
discovery_path: academic|вертикальное сельское хозяйство|ru
root: study-smith-2024
chain_len: 0
credibility: 5
---
```

**Считать пустых агентов:**

- Файл `sources/NN.md` существует, но пуст (только frontmatter, `chain_len: 0` или пусто) — агент вернул пустоту
- Файлы считаны последовательно по номерам NN, `sources/NN.md` отсутствует → агент не запускался вовсе (это ошибка инструментовки, должна логироваться отдельно)
- Актуально только для режима off: в режиме on число запущенных агентов может отличаться из-за адаптивной аллокации

**Формула:**
```
пусты = count(files sources/NN.md where chain_len == 0 or body == "")
запущено = count(files sources/NN.md)
```

### 3. Порядок прогона одной пары (on/off)

**Перед запуском:**

1. **Зафиксировать вопрос и параметры:**
   - Выбрать тему из списка выше
   - Зафиксировать текст вопроса (скопировать в заметки)
   - Зафиксировать depth (shallow / medium / deep)
   - Зафиксировать жанр и жанр-требования (если есть)

2. **Выбрать пару одинаковых условий:**
   - Одинаковый выбор каналов в source_dispatch (или автоматический dispatch)
   - Одинаковые шанцы получить отступления от план (количество deviation-будетов не меняется)
   - Одинаковая инструментовка

3. **Зафиксировать внешние условия:**
   - Дата/время начала прогона
   - Состояние `~/.claude/deepdive-state/` (наличие `priors.json`)
   - Версия скилла / коммит (git rev-parse HEAD)

4. **Запуск режима on:**
   ```bash
   # переменная не задана (по умолчанию режим on)
   unset DEEPDIVE_SWARM
   # запустить прогон обычным способом, зафиксировать run_id
   ```

5. **Запуск режима off:**
   ```bash
   export DEEPDIVE_SWARM=off
   # запустить прогон с точно теми же параметрами, зафиксировать run_id
   ```

**После каждого прогона:**

6. **Сбор данных:**
   - Скопировать полный текст claims.csv в локальный отчёт
   - Скопировать список файлов sources/ (например, `ls -l sources/ | tail -n +2`)
   - Подсчитать метрики (см. п. 2 выше)
   - Занести в таблицу выше

7. **Проверка целостности:**
   - Убедиться, что `dissent` колонка корректно заполнена (контр-улики тоже считаются)
   - Проверить, что все источники имеют `discovery_path` (если нет — ошибка диспатча, не замера)

**Логирование между попытками:**

Если замер прерывается на середине пары или требует повтора одного режима:
- Сохранить перепрогон отдельно с пометкой (на_повтор, контрольная_была_нарушена)
- Не использовать перепрогоны в итоговом расчёте

## Ожидаемые результаты

**На успешный замер:**
- На 5 темах среднее число пустых агентов в режиме on будет ≤ чем в режиме off (экономия бюджета)
- Доля triangulated не упадёт (триангуляция в безопасности)
- Отчёты режимов on/off будут оформлены рядом в одном документе с выводом

**На отката:**
- Немедленно откатить коммиты Task 1–9
- Пересмотреть границу между обязательной и свободной частью бюджета в run_search_loop
